# План wsdbus: общий API рабочего стола и оконный демон Hyprland

**Статус:** план, реализация не начата.
**Дата:** 2026-10-17.
**Связанные проекты:** wstouchbar (`docs/architecture/07-desktop.md`, этап 5),
wswidgets (адаптер GNOME), wsconfig (`docs/plans/hyprland.md`).

## Цель

Один контракт фактов и команд рабочего стола вместо отдельной интеграции в
каждом проекте. Плавающие окна в Hyprland без переноса Hyprstack целиком:
собственный демон на Rust с модульной структурой.

Готово, когда:

- **контракт:** wstouchbar и wswidgets получают факты и отдают команды через
  wsdbus в GNOME и в Hyprland, не зная, какое окружение работает;
- **GNOME:** одно расширение `wsdbus` отдаёт весь контракт. Сторонние
  Window Monitor Pro и window-control и запланированное расширение wstouchbar
  не нужны; `ws-window` работает через wsdbus в обеих сессиях;
- **Hyprland:** демон `wsdbusd` отдаёт контракт (модуль `provider`) и, если
  включён модуль `policy`, ведёт плавающие рабочие столы, сворачивание,
  разворачивание и привязку к половинам и четвертям экрана;
- **интерфейс:** свёрнутые окна возвращаются из интерфейса, `Alt+Tab`
  переключает окна с показом списка;
- **тесты:** обычный `cargo test` проходит без Hyprland, GNOME и D-Bus. Живые
  тесты идут во вложенном Hyprland и в сессии GNOME по чек-листу.

## Основания

Разбор проектов из предложения «upstream-first Desktop Framework»
(2026-10-17). Ревизии: Hyprland `v0.56.2` (`efb5099`), Hyprstack `6531731`,
Omarchy `cce8b1c`, Caelestia shell `0ed56a8`, dots `f4bb062`, Quickshell
`2b4501a`.

- **Hyprstack** (GPL-3.0, создан 2026-10-15) — форк Caelestia shell и dots
  с движком `layouts.lua` (1902 непустые строки) и изменённым hyprbars
  (около 4400 строк C++: заголовки, ввод в stacking, snap, overview,
  анимации). `layouts.lua` при загрузке назначает 23 сочетания, 13 обработчиков,
  13 правил и 15 вызовов `hl.config`, а правил для Telegram в нём 59 строк. Возврат
  свёрнутых окон, `Alt+Tab` и overview выполняет его оболочка. Движок от
  оболочки не отделяется. Нативный модуль требует ровно Hyprland 0.56.2.
- **Omarchy** (MIT) — дистрибутив на Arch со своей оболочкой. Полезен
  `default/hypr/workspace-modes.lua` (550 строк с `helpers.lua` — 724):
  плавающий режим по рабочим столам на тегах окна, без обязательного плагина
  заголовков.
- **Caelestia** (GPL-3.0, релизы с тегами, ветка `stable`) — оболочка без
  оконного движка и панели задач. Ветка `feat/plugins` заброшена с 2026-08-03.
- **Hyprland 0.56.2**, проверено по исходникам:
  - socket2 отдаёт `openwindow`, `closewindow`, `movewindowv2`,
    `changefloatingmode`, `fullscreen`, `activewindowv2`, события рабочих
    столов и `minimized` (запрос клиента через foreign-toplevel);
  - правила окон выбирают по `workspace` и `tag`;
  - `hyprctl clients -j` отдаёт `stableId` (счётчик, не повторяется в
    экземпляре) и `tags`;
  - есть `hyprctl eval`, Lua-события `window.open_early` и `config.reloaded`,
    протокол global shortcuts, диспетчер `sendshortcut`, запрос
    `hyprctl locked`;
  - события о блокировке экрана нет ни в socket2, ни в Lua.
- **Quickshell:** для QML из D-Bus доступен только DBusMenu. Есть `Socket`,
  `Process` и `SplitParser`. Модули `wlr-foreign-toplevel` и `ext-workspace-v1`
  есть, но в GNOME таких протоколов нет.
- **Установленные расширения GNOME** (mbp16, 13 включённых), что пересекается
  с контрактом:
  - `window-control@carlo9890.github.io` (стороннее, 2652 строки) — D-Bus
    управления окнами. Пользуется им только `libexec/ws-window` wsconfig
    (`ListDetailed`, `Minimize`, `Close`): сочетания «скрыть приложение»,
    «скрыть остальные», «свернуть», «закрыть»;
  - `window-monitor-pro@…` (стороннее, 180 строк) — фокус и список окон.
    Ставилось, чтобы wstouchbar получал активное окно; сейчас им никто не
    пользуется;
  - `workstation-input-source@local` (wsconfig) — раскладка, CapsLock,
    Fn+CapsLock, LED. Раскладка — факт рабочего стола, остальное — логика
    клавиатуры wsconfig;
  - `xremap@k0kubun.com` — собственный протокол xremap (`com.k0kubun.Xremap`);
  - остальные (`workstation-smart-popup`, `-dock-spring`, `-hibernate`,
    `-widgets`, Tiling Assistant, Ubuntu Dock, AppIndicators, DING, поиск) —
    интерфейс GNOME, к контракту отношения не имеют.

владелец согласился. «Предложение» — часть плана, которую владелец отдельно
не обсуждал; подтверждается чтением плана.

## Процессы

```text
потребители:  touchbar-session ─ client (Rust)
              wswidgets / интерфейс окон (QML) ─ Process: wsdbus-ctl watch --json
                         │  session bus: io.github.kkkingqz.WsDbus
поставщик:    GNOME — расширение wsdbus@kkkingqz.github.io
              Hyprland — wsdbusd: provider + policy ─ socket1/socket2, global shortcuts
внутри Hyprland: прослойка Lua (сочетания → global, статические правила), hyprbars
```

В сессии работает ровно один поставщик: имя на шине занимает расширение в
GNOME или `wsdbusd` в Hyprland. Без поставщика потребители работают как сейчас
без бэкенда (`null` в wstouchbar).

## Контракт v1

Имя `io.github.kkkingqz.WsDbus`, объект `/io/github/kkkingqz/WsDbus`,
интерфейс `io.github.kkkingqz.WsDbus.Desktop1`. Несовместимое изменение —
новый интерфейс `Desktop2` рядом со старым.

**Свойства:** `Version`, `Provider` (`gnome`, `hyprland`), `Capabilities`
(список поддерживаемых фактов и команд).

**Факты** (`GetState() → (t revision, a{sv} facts)`, сигнал
`StateChanged(t revision, a{sv} changed, as removed)`):

| Факт | Тип | Смысл |
|---|---|---|
| `focus.app` | текст | нормализованный id приложения в фокусе; нет фокуса — факта нет |
| `focus.class` | текст | исходный class / WM class |
| `focus.fullscreen` | логический | окно в фокусе на весь экран |
| `session.locked` | логический | экран заблокирован |
| `appearance.scheme` | текст | `light` или `dark` |
| `appearance.accent` | текст | `#rrggbb` |
| `appearance.font` | текст | шрифт интерфейса |
| `workspaces` | записи | `{id, name, monitor, active, mode?}` |
| `workspace.active` | текст | активный стол монитора в фокусе |
| `display.brightness` | число | 0.0–1.0, только GNOME |
| `keyboard.layout` | текст | активная раскладка (`us`, `ru`, `ua`; id источника ввода) |

**Окна** (`GetWindows() → (t revision, aa{sv})`, сигнал
`WindowsChanged(t revision, aa{sv} upserted, as removed)`): `id`, `app`,
`class`, `title`, `workspace`, `monitor`, флаги `focused`, `minimized`,
`maximized`, `floating`, `fullscreen`. Окна отдельно от фактов, чтобы смена
заголовка не пересылала все факты.

**Ревизия** одна на всё состояние. Клиент берёт снимок, затем применяет
изменения с большей ревизией. При пропуске ревизии он запрашивает снимок
заново.

**Id окна** — непрозрачная строка в пределах сессии: в Hyprland из `stableId`
и подписи экземпляра, в GNOME из `Meta.Window.get_stable_sequence()`. Команда
с неизвестным или закрытым id возвращает `StaleWindow`, а не действует на
другое окно.

**Команды:** `Shortcut(as keys, s app)`, `LaunchApp(s id)`,
`ActivateWorkspace(s id)`, `WindowAction(s id, s action)` с действиями
`activate`, `close`, `minimize`, `restore`, `toggle-maximize`,
`SetWorkspaceMode(s id, s mode)` (только Hyprland с `policy`). Ошибки D-Bus:
`…Error.Unsupported`, `…Error.StaleWindow`, `…Error.Locked`, `…Error.Denied`.
`Shortcut` и `LaunchApp` при заблокированном экране отклоняются, как в
wstouchbar.

**`app.id`:** id desktop-файла без `.desktop`; не найден — `wmclass:<class>`.
В Hyprland поиск по `StartupWMClass`, имени desktop-файла и id Flatpak в
`XDG_DATA_DIRS`. Правило описано в `spec/`, случаи лежат в
`spec/appid-cases.json`, их проходят и Rust-реализация, и тесты расширения
GNOME.

**Доверие (W20).** Процессы пользователя без песочницы уже внутри границы
доверия. Угроза — приложение в песочнице, у которого есть доступ к сессионной
шине: Flatpak с `--socket=session-bus` может занять любое имя, поэтому список
доверенных имён от него не защищает. Чтение фактов и окон открыто всем.
Изменяющие методы поставщик проверяет по отправителю: PID через
`GetConnectionUnixProcessID`, затем признаки песочницы —
`/proc/PID/root/.flatpak-info`, cgroup `app-flatpak-*` и `snap.*`, как
проверяет xdg-desktop-portal. Процессу в песочнице или процессу, который не
удалось проверить, — `…Error.Denied`. Проверка одна: в `wsdbusd` на Rust и в
расширении GNOME на JS, общие случаи — в `spec/`. Её надёжность для процессов
в другом user namespace (bubblewrap) проверяется на этапе 1. Поставщик
принимает сигналы только от своих источников.

## `wsdbus-ctl`

- `watch --json` — снимок, затем изменения, по одной строке JSON
  (`{"revision":…, "facts":…}`, `{"revision":…, "windows":…}`), при
  переподключении поставщика — новый снимок;
- `state`, `windows` — разовый вывод;
- `shortcut`, `launch`, `workspace`, `window ID ACTION`, `mode` — команды;
- коды выхода различают `unsupported`, `stale`, `locked`, нет поставщика.

QML запускает `watch` через `Process` и читает `SplitParser`, команды — разовым
`Process`.

## Поставщик GNOME

Одно расширение, около 400–600 строк JS. Источники: `Shell.WindowTracker`
(фокус и `app.id`), `Meta.Window` (окна, полноэкранный режим, действия:
`activate`, `minimize`, `unminimize`, `maximize`, `delete`),
`global.workspace_manager`, `Main.sessionMode.isLocked`,
`org.gnome.desktop.interface`, `org.gnome.Shell.Brightness`, InputSourceManager
(только чтение `keyboard.layout`). Нажатия —
виртуальное устройство Clutter, как в плане wstouchbar. Запуск —
`Shell.AppSystem`. Режима стола нет: `SetWorkspaceMode` отвечает
`Unsupported`.

## Поставщик Hyprland: `wsdbusd`

**Слои:**

1. **Внутри Hyprland:** прослойка Lua около 150 строк — сочетания вызывают
   `hl.dsp.global("wsdbus:…")`, статические правила; логики нет. hyprbars из
   hyprland-plugins той же версии, что Hyprland; кнопки отправляют
   `wsdbus:minimize`, `wsdbus:maximize`, `wsdbus:close`.
2. **`provider`:** подключение к IPC, `hypr-model`, `app.id`, контракт;
   `keyboard.layout` — из события `activelayout`.
3. **`policy`:** правила окон поверх той же модели.

**Первая версия `policy`:**

- режим задаётся для каждого стола (W19): в конфигурации режим по умолчанию
  для каждого стола (`tiling` или `floating`), сочетание меняет режим текущего,
  другое — всех столов разом (массовая операция над той же моделью). Общие
  настройки Hyprland, которые зависят от режима (фокус под мышью и др.),
  переключаются при смене активного стола, как в Omarchy;
- плавающий режим рабочего стола: новые окна плавают по правилу Hyprland ещё
  до показа (правило по `workspace` или `window.open_early`); тег
  «сделано режимом» и тег «на плавающем столе», как в Omarchy; при выходе из
  режима в тайлинг возвращаются только окна с первым тегом;
- свернуть: перенос на `special:wsdbus-minimized-<monitor>` с записью, откуда
  окно ушло (стол, геометрия, плавающее ли); восстановить по записи; запрос
  `minimized` от приложения обрабатывается так же;
- развернуть и вернуть с сохранённой геометрией;
- половины и четверти экрана сочетаниями;
- `Alt+Tab`: порядок по последнему фокусу, включая свёрнутые, показ — в
  интерфейсе окон;
- настройки Hyprland, которые меняет режим (отступы, рамки, фокус под мышью),
  сохраняются и возвращаются;
- состояние сессии в `$XDG_RUNTIME_DIR` по `HYPRLAND_INSTANCE_SIGNATURE`;
  после reload и перезапуска демона — пересинхронизация по тегам и файлу.

**Не в первой версии:** snap перетаскиванием с подсказкой зоны (нужен ввод в
compositor), overview, анимация сворачивания в панель.

## Потребители

- **wstouchbar.** Этап 5 вместо `touchbar-desktop-gnome` и своего расширения
  получает `touchbar-desktop-wsdbus` на `wsdbus-client`. Отдельный бэкенд
  Hyprland не нужен. Решение D15 wstouchbar («своё расширение Shell, бэкенд
  в процессе сессии») пересматривается в его журнале при начале этапа 5;
  модель доверия его расширения (команды только от владельца имени сессии)
  заменяется проверкой песочницы W20.
  `display.brightness` в Hyprland — свой `brightnessctl`.
- **wswidgets.** Через `wsdbus-ctl watch --json`: `session.locked` и
  `appearance.scheme`. Адаптер GNOME (панель, размещение, стиль) не меняется.
  Адаптер Hyprland — отдельная задача wswidgets.
- **Интерфейс окон** (свёрнутые и `Alt+Tab`) — QML на `wsdbus-ctl`, только для
  Hyprland (W18). Где он живёт — открытый вопрос 2.
- **`ws-window` wsconfig.** Вместо D-Bus window-control — `wsdbus-ctl windows`
  и `wsdbus-ctl window ID minimize|close`. «Скрыть приложение» и «скрыть
  остальные» — логика `ws-window` поверх списка окон и `app`. Те же
  сочетания работают в Hyprland.

|---|---|---|
| **0. Прототип** | проверка допущений (ниже) | все пункты подтверждены или найдены обходы, план уточнён |
| **1. Контракт** | `spec/`, `wsdbus-contract`, `wsdbus-client`, `wsdbus-fake`, `wsdbus-appid`, `wsdbus-ctl`, проверка песочницы отправителя (W20) | клиент и `ctl` проходят тесты против `wsdbus-fake`; случаи `app.id` проходят; процесс Flatpak получает `Denied`, обычный процесс — нет |
| **2. `provider` Hyprland** | `hypr-ipc`, `hypr-model`, `wsdbusd-api`, `wsdbusd` без `policy` | во вложенном Hyprland `wsdbus-ctl watch` показывает фокус, столы и окна; повторы записанных потоков проходят |
| **3. `policy`** | `hypr-policy`, `hypr-exec`, `hypr-store`, `hypr-shortcuts`, прослойка Lua, hyprbars | первая версия `policy` работает во вложенном Hyprland по чек-листу; перезапуск демона и reload не теряют состояние |

| **5. Интерфейс окон** | QML свёрнутых окон и `Alt+Tab` | в Hyprland свёрнутые возвращаются из интерфейса, `Alt+Tab` показывает список |
| **6. Интеграция** | Nix flake и HM-модуль, wsconfig: расширение в списке GNOME, `wsdbusd` в generation Hyprland, `ws-window` на `ctl`, удаление window-control и Window Monitor Pro, `ws check`; wswidgets на `ctl` | wsconfig ставит wsdbus в обеих сессиях; сочетания `ws-window` работают в GNOME и Hyprland; сторонних расширений окон нет; проверки зелёные |

Этапы 0–3 идут во вложенном Hyprland и не ждут миграции из
`docs/plans/hyprland.md` wsconfig. Этап 6 для Hyprland — после этапов 2–3
того плана (runtime и управление сессией). Подключение в wstouchbar — его
этап 5.

### Этап 0: что проверить

1. Hyprland 0.56.2 запускается окном внутри сессии GNOME, IPC доступен.
2. Новое окно на плавающем столе показывается сразу плавающим, без рывка:
   правило по `workspace`, иначе `window.open_early`.
3. Процесс на Rust получает действия global shortcuts от
   `hl.dsp.global("wsdbus:…")`.
4. Кнопка hyprbars вызывает `global` и доходит до демона.
5. Источник `session.locked` в Hyprland: событие от locker, `LockedHint`
   logind или запрос `hyprctl locked` без постоянного опроса.
6. Источник `appearance.*` в Hyprland: `org.freedesktop.appearance` портала
   Settings или схема Caelestia.
7. `sendshortcut` доставляет сочетание в окно не в фокусе так, как нужно
   `Shortcut(keys, app)`.

Итог этапа — заметка в `docs/validation/stage-0.md`: что подтвердилось, какие
обходы приняты, изменения плана.

## Тестирование

- `hypr-model`, `hypr-policy`, `wsdbus-contract` — таблицы и property-тесты
  без IO;
- `hypr-ipc` — разбор записанных событий и JSON;
- `tests/` — повтор записанных потоков socket2 через `hypr-policy` и
  поддельный `hypr-exec`;
- потребители и `ctl` — против `wsdbus-fake` на частной шине;
- живые тесты — вложенный Hyprland и сессия GNOME по чек-листу
  `docs/testing.md`.

## Риски

| Риск | Что делаем |
|---|---|
| Синтаксис правил и Lua API Hyprland меняются | всё это только в прослойке Lua; проверка при обновлении Hyprland в wsconfig |
| hyprbars отстаёт от релиза Hyprland | демон работает без заголовков, действия доступны сочетаниями |
| Рывок нового окна на плавающем столе | этап 0, пункт 2 |
| Пограничные случаи: несколько мониторов, диалоги, XWayland, Steam/Proton/Wine | сценарии в `tests/` по каждому найденному случаю; особые правила приложений — данные конфигурации, не код |
| Окна двигает и пользователь, и демон | теги на окне — источник истины, демон не возвращает окна, которые не трогал |
| Несовместимое изменение контракта | новый интерфейс `Desktop2`, возможности, проверка версии клиентом |

## Открытые вопросы

1. **Где интерфейс окон** (свёрнутые и `Alt+Tab`, только Hyprland, W18).
   Не определено (2026-10-17); решается до этапа 5. Варианты:
   - отдельное приложение Quickshell в wsdbus (`wsdbus-ui`) — рядом с
     контрактом, не зависит от Caelestia и wswidgets; ещё один процесс Qt и
     своя тема;
   - новая поверхность wswidgets — общий процесс и тема; привязывает
     wswidgets к оконной модели Hyprland, нужен захват клавиатуры;
   - доработка Caelestia — плагинов нет, по сути форк;
   - готовая панель задач (waybar `wlr/taskbar`, nwg-dock) — не знает
     состояния «свёрнуто», `Alt+Tab` не решает;
   - Touch Bar через wstouchbar — только mbp16, как дополнение.
