# План 1: контракт и GNOME

**Статус:** этапы 1 и 2 реализованы и проверены: в GNOME Shell 50 без экрана
(`gnome-extension/tests/headless.sh`), вызовом из Flatpak и в сессии mbp16 по
`docs/testing.md`. Открыто: `Shortcut` при активной русской раскладке в живой
сессии не доходит до Ptyxis (без экрана Ctrl+Q в Calculator работает);
исправление `ffdfbb4` ждёт повторного входа. Этап 3 реализован: Nix flake и
HM-модуль (`2c89da4`), wswidgets следит за `session.locked` и
`appearance.scheme` (`827fc4c`), ядро wsconfig — `ws-window` на
`wsdbus-ctl`, поставщик в списке расширений, Window Control и Window Monitor
Pro убраны из шаблона (`69d021b`). Осталось на mbp16: `ws apply`, проверка
по `docs/testing.md` (этап 3), затем удаление Window Control из конфигурации.
**Дата:** 2026-10-17.
**Решения:** [журнал](../decisions.md) W1–W22.
**Второй план:** [стек Hyprland](2026-10-17-hyprland.md) — поставщик Hyprland,
правила окон, интерфейс окон. Этот план от него не зависит.
**Связанные проекты:** wstouchbar (`docs/architecture/07-desktop.md`, этап 5),
wswidgets (адаптер GNOME), wsconfig (`gnome/`, `libexec/ws-window`).

## Цель

Один контракт фактов и команд рабочего стола вместо отдельной интеграции в
каждом проекте, и его поставщик для GNOME. Без Hyprland: контракт сразу
описывает и его возможности, но реализует их план 2.

Готово, когда:

- **контракт:** описан в `spec/`, реализован в `wsdbus-contract`, клиент
  `wsdbus-client` и `wsdbus-ctl` проходят тесты против `wsdbus-fake`;
- **GNOME:** одно расширение `wsdbus` отдаёт весь контракт; процесс Flatpak
  получает `Denied` на изменяющие команды;
- **wsconfig:** `ws-window` работает через `wsdbus-ctl`; сторонних
  window-control и Window Monitor Pro нет; `ws check` зелёный;
- **wswidgets:** реагирует на `session.locked` и `appearance.scheme` через
  `wsdbus-ctl watch --json`;
- **wstouchbar:** клиент и поддельный поставщик готовы для его этапа 5;
- **тесты:** обычный `cargo test` проходит без GNOME и сессионной шины;
  живые тесты — в сессии GNOME по чек-листу.

## Основания

- **Установленные расширения GNOME** (mbp16, 13 включённых), что пересекается
  с контрактом:
  - `window-control@carlo9890.github.io` (стороннее, 2652 строки) — D-Bus
    управления окнами. Пользуется им только `libexec/ws-window` wsconfig
    (`ListDetailed`, `Minimize`, `Close`): сочетания «скрыть приложение»,
    «скрыть остальные», «свернуть», «закрыть»;
  - `window-monitor-pro@…` (стороннее, 180 строк) — фокус и список окон.
    Ставилось, чтобы wstouchbar получал активное окно; сейчас им никто не
    пользуется;
  - `workstation-input-source@local` (wsconfig) — раскладка, CapsLock,
    Fn+CapsLock, LED. Раскладка — факт рабочего стола, остальное — логика
    клавиатуры wsconfig;
  - `xremap@k0kubun.com` — собственный протокол xremap (`com.k0kubun.Xremap`);
  - остальные (`workstation-smart-popup`, `-dock-spring`, `-hibernate`,
    `-widgets`, Tiling Assistant, Ubuntu Dock, AppIndicators, DING, поиск) —
    интерфейс GNOME, к контракту отношения не имеют.
- **Дублирование без контракта:** активное окно в GNOME ловят Window Monitor
  Pro, расширение xremap и запланированное расширение wstouchbar; тему —
  расширение wswidgets и бэкенд wstouchbar.
- **Quickshell** (`2b4501a`): для QML из D-Bus доступен только DBusMenu. Есть
  `Socket`, `Process` и `SplitParser`.

## Процессы

```text
потребители:  touchbar-session ─ wsdbus-client (Rust)
              wswidgets (QML) ─ Process: wsdbus-ctl watch --json
              ws-window ─ wsdbus-ctl
                         │  session bus: io.github.kkkingqz.WsDbus
поставщик:    GNOME — расширение wsdbus@kkkingqz.github.io
              Hyprland — wsdbusd (план 2)
```

В сессии работает ровно один поставщик. Без поставщика потребители работают
как сейчас без бэкенда (`null` в wstouchbar), `wsdbus-ctl` возвращает код
«нет поставщика».

## Контракт v1

Имя `io.github.kkkingqz.WsDbus`, объект `/io/github/kkkingqz/WsDbus`,
интерфейс `io.github.kkkingqz.WsDbus.Desktop1`. Несовместимое изменение —
новый интерфейс `Desktop2` рядом со старым.

**Свойства:** `Version`, `Provider` (`gnome`, `hyprland`), `Capabilities`
(список поддерживаемых фактов и команд).

**Факты** (`GetState() → (t revision, a{sv} facts)`, сигнал
`StateChanged(t revision, a{sv} changed, as removed)`):

| Факт | Тип | Смысл |
|---|---|---|
| `focus.app` | текст | нормализованный id приложения в фокусе; нет фокуса — факта нет |
| `focus.class` | текст | исходный class / WM class |
| `focus.fullscreen` | логический | окно в фокусе на весь экран |
| `session.locked` | логический | экран заблокирован |
| `appearance.scheme` | текст | `light` или `dark` |
| `appearance.accent` | текст | `#rrggbb` |
| `appearance.font` | текст | шрифт интерфейса |
| `workspaces` | записи | `{id, name, monitor, active, mode?}`; `mode` — только Hyprland с `policy` |
| `workspace.active` | текст | активный стол монитора в фокусе |
| `display.brightness` | число | 0.0–1.0, только GNOME (W5) |
| `keyboard.layout` | текст | активная раскладка (`us`, `ru`, `ua`; id источника ввода), только чтение (W16) |

**Окна** (`GetWindows() → (t revision, aa{sv})`, сигнал
`WindowsChanged(t revision, aa{sv} upserted, as removed)`): `id`, `app`,
`class`, `title`, `workspace`, `monitor`, флаги `focused`, `minimized`,
`maximized`, `floating`, `fullscreen`. Окна отдельно от фактов, чтобы смена
заголовка не пересылала все факты.

**Ревизия** одна на всё состояние. Клиент берёт снимок, затем применяет
изменения с большей ревизией. При пропуске ревизии он запрашивает снимок
заново.

**Id окна** — непрозрачная строка в пределах сессии: в GNOME из
`Meta.Window.get_stable_sequence()`, в Hyprland из `stableId` и подписи
экземпляра. Команда с неизвестным или закрытым id возвращает `StaleWindow`, а
не действует на другое окно.

**Команды:** `Shortcut(as keys, s app)`, `LaunchApp(s id)`,
`ActivateWorkspace(s id)`, `WindowAction(s id, s action)` с действиями
`activate`, `close`, `minimize`, `restore`, `toggle-maximize`,
`SetWorkspaceMode(s id, s mode)` (только Hyprland с `policy`), для
wstouchbar — `Key(s key, b pressed)` и `SetBrightness(d level)` (W23).
Ошибки D-Bus:
`…Error.Unsupported`, `…Error.StaleWindow`, `…Error.Locked`, `…Error.Denied`.
`Shortcut`, `LaunchApp` и нажатие в `Key` при заблокированном экране
отклоняются, как в wstouchbar. Перемещения, размера и геометрии в v1 нет (W14).

**`app.id` (W6):** id desktop-файла без `.desktop`; не найден —
`wmclass:<class>`. Правило описано в `spec/`, случаи лежат в
`spec/appid-cases.json`. В GNOME id даёт `Shell.WindowTracker`, тесты
расширения проходят случаи; поиск desktop-файлов на Rust для Hyprland — в
плане 2.

**Доверие (W20).** Процессы пользователя без песочницы уже внутри границы
доверия. Угроза — приложение в песочнице, у которого есть доступ к сессионной
шине: Flatpak с `--socket=session-bus` может занять любое имя, поэтому список
доверенных имён от него не защищает. Чтение фактов и окон открыто всем.
Изменяющие методы поставщик проверяет по отправителю: PID через
`GetConnectionUnixProcessID`, затем признаки песочницы —
`/proc/PID/root/.flatpak-info`, cgroup `app-flatpak-*` и `snap.*`, как
проверяет xdg-desktop-portal. Процессу в песочнице или процессу, который не
удалось проверить, — `…Error.Denied`. Случаи проверки — в `spec/`, их
проходит расширение GNOME (этот план) и `wsdbusd` (план 2). Поставщик
принимает сигналы только от своих источников.

## `wsdbus-ctl`

- `watch --json` — снимок, затем изменения, по одной строке JSON
  (`{"revision":…, "facts":…}`, `{"revision":…, "windows":…}`), при
  переподключении поставщика — новый снимок;
- `state`, `windows` — разовый вывод;
- `shortcut`, `launch`, `workspace`, `window ID ACTION`, `mode` — команды;
- коды выхода различают `unsupported`, `stale`, `locked`, `denied`, нет
  поставщика.

QML запускает `watch` через `Process` и читает `SplitParser`, команды — разовым
`Process` (W9).

## Состав (этот план)

```text
spec/                    D-Bus XML, описание фактов, appid-cases.json,
                         sandbox-cases.json (русский)
crates/
  wsdbus-contract/       типы фактов, окон, команд, ошибок; правило app.id; без IO
  wsdbus-client/         клиент zbus: снимок, изменения, переподключение, backoff
  wsdbus-fake/           поддельный поставщик для тестов потребителей
bin/
  wsdbus-ctl/            CLI
gnome-extension/         поставщик GNOME и его тесты
nix/                     пакеты, HM-модуль
```

Rust, лицензия MIT (W21). Крейты Hyprland добавляет план 2.

## Поставщик GNOME

Одно расширение, около 400–600 строк JS. Источники: `Shell.WindowTracker`
(фокус и `app.id`), `Meta.Window` (окна, полноэкранный режим, действия:
`activate`, `minimize`, `unminimize`, `maximize`, `delete`),
`global.workspace_manager`, `Main.sessionMode.isLocked`,
`org.gnome.desktop.interface`, `org.gnome.Shell.Brightness`,
InputSourceManager (только чтение `keyboard.layout`),
`Main.brightnessManager.globalScale` (факт и `SetBrightness`; D-Bus
`org.gnome.Shell.Brightness` в GNOME 50 текущий уровень не отдаёт). Нажатия
(`Shortcut`, `Key`) — виртуальное
устройство Clutter, как в плане wstouchbar. Запуск — `Shell.AppSystem`.
Режима стола нет: `SetWorkspaceMode` отвечает `Unsupported`; `policy` в GNOME
не нужен (W18).

Логика без GNOME Shell (сопоставление фактов, ревизии, проверка песочницы,
случаи `app.id`) — в отдельных модулях `.mjs`, их проверяют тесты на GJS, как в
wswidgets.

## Потребители

- **wstouchbar.** Этап 5 вместо `touchbar-desktop-gnome` и своего расширения
  получает `touchbar-desktop-wsdbus` на `wsdbus-client`. Решение D15
  wstouchbar («своё расширение Shell, бэкенд в процессе сессии»)
  пересматривается в его журнале при начале этапа 5; модель доверия его
  расширения (команды только от владельца имени сессии) заменяется проверкой
  песочницы W20. Отдельный бэкенд Hyprland ему не понадобится.
- **wswidgets.** Через `wsdbus-ctl watch --json`: `session.locked` и
  `appearance.scheme` (W10). Адаптер GNOME (панель, размещение, стиль) не
  меняется.
- **`ws-window` wsconfig** (W14). Вместо D-Bus window-control —
  `wsdbus-ctl windows` и `wsdbus-ctl window ID minimize|close`. «Скрыть
  приложение» и «скрыть остальные» — логика `ws-window` поверх списка окон и
  `app`. Те же сочетания потом работают в Hyprland (план 2).

## Тестирование

- `wsdbus-contract` — таблицы и property-тесты без IO (кодирование фактов и
  окон туда и обратно, правило `app.id`);
- `wsdbus-client`, `wsdbus-ctl` — против `wsdbus-fake` на частном
  `dbus-daemon`;
- расширение — тесты GJS для модулей без GNOME Shell;
- живые тесты — сессия GNOME по чек-листу `docs/testing.md`: факты, окна,
  команды, блокировка, Flatpak-процесс, `ws-window`.

## Риски

| Риск | Что делаем |
|---|---|
| API GNOME Shell меняется между версиями | расширение минимальное, логика в `.mjs` без Shell; поддерживаемые версии в `metadata.json`, целевая — Ubuntu 26.04 |
| Проверка песочницы не видит процесс в другом user namespace (bubblewrap) | этап 2: проверка на реальном Flatpak; не удалось проверить — `Denied` |
| `ws-window` теряет сочетания при переходе | window-control убирается только после того, как `ws-window` через `ctl` проверен в живой сессии |
| Несовместимое изменение контракта | новый интерфейс `Desktop2`, возможности, проверка версии клиентом |
