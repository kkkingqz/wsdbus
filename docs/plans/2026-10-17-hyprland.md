# План 2: стек Hyprland

**Статус:** план, реализация не начата.
**Дата:** 2026-10-17.
**Решения:** [журнал](../decisions.md) W1–W22.
**Зависит от:** [плана 1](2026-10-17-core.md), этап 1 — контракт v1,
`wsdbus-client`, `wsdbus-fake`, `wsdbus-ctl`. Этап 0 этого плана от него не
зависит.
**Связанные проекты:** wsconfig `docs/plans/hyprland.md` (Hyprland и
Caelestia рядом с GNOME: runtime, GDM-сессия, порталы, клавиатура) — этот план
даёт ему оконный слой и поставщика контракта.

## Цель

Плавающие окна в Hyprland без переноса Hyprstack целиком: собственный демон
на Rust с модульной структурой (W1). Тот же демон — поставщик контракта
wsdbus в Hyprland, поэтому wstouchbar, wswidgets и `ws-window` работают в
Hyprland без своих бэкендов.

Готово, когда:

- **`provider`:** `wsdbusd` отдаёт контракт v1 в Hyprland; `wsdbus-ctl watch`
  показывает фокус, столы, окна, раскладку, блокировку и тему;
- **`policy`:** плавающие рабочие столы, сворачивание, разворачивание,
  половины и четверти экрана, `Alt+Tab`; перезапуск демона и reload Hyprland
  не теряют состояние;
- **интерфейс:** свёрнутые окна возвращаются из интерфейса, `Alt+Tab`
  показывает список;
- **wsconfig:** desktop generation Hyprland ставит `wsdbusd`, прослойку Lua и
  hyprbars; сочетания `ws-window` работают и в Hyprland;
- **тесты:** обычный `cargo test` проходит без Hyprland и сессионной шины;
  живые тесты — во вложенном Hyprland по чек-листу.

## Основания

Разбор проектов из предложения «upstream-first Desktop Framework»
(2026-10-17). Ревизии: Hyprland `v0.56.2` (`efb5099`), Hyprstack `6531731`,
Omarchy `cce8b1c`, Caelestia shell `0ed56a8`, dots `f4bb062`, Quickshell
`2b4501a`.

- **Hyprstack** (GPL-3.0, создан 2026-10-15) — форк Caelestia shell и dots
  с движком `layouts.lua` (1902 непустые строки) и изменённым hyprbars
  (около 4400 строк C++: заголовки, ввод в stacking, snap, overview,
  анимации). `layouts.lua` при загрузке назначает 23 сочетания, 13
  обработчиков, 13 правил и 15 вызовов `hl.config`, а правил для Telegram в
  нём 59 строк. Возврат свёрнутых окон, `Alt+Tab` и overview выполняет его
  оболочка. Движок от оболочки не отделяется. Нативный модуль требует ровно
  Hyprland 0.56.2.
- **Omarchy** (MIT) — дистрибутив на Arch со своей оболочкой. Полезен
  `default/hypr/workspace-modes.lua` (550 строк с `helpers.lua` — 724):
  плавающий режим по рабочим столам на тегах окна, без обязательного плагина
  заголовков.
- **Caelestia** (GPL-3.0, релизы с тегами, ветка `stable`) — оболочка без
  оконного движка и панели задач. Ветка `feat/plugins` заброшена с 2026-08-03.
- **Hyprland 0.56.2**, проверено по исходникам:
  - socket2 отдаёт `openwindow`, `closewindow`, `movewindowv2`,
    `changefloatingmode`, `fullscreen`, `activewindowv2`, `activelayout`,
    события рабочих столов и `minimized` (запрос клиента через
    foreign-toplevel);
  - правила окон выбирают по `workspace` и `tag`;
  - `hyprctl clients -j` отдаёт `stableId` (счётчик, не повторяется в
    экземпляре) и `tags`;
  - есть `hyprctl eval`, Lua-события `window.open_early` и `config.reloaded`,
    протокол global shortcuts, диспетчер `sendshortcut`, запрос
    `hyprctl locked`;
  - события о блокировке экрана нет ни в socket2, ни в Lua.
- **Quickshell:** модули `wlr-foreign-toplevel` и `ext-workspace-v1` есть;
  Hyprland их поддерживает. Состояние «свёрнуто» Hyprland через протокол, по
  всей видимости, не сообщает: сам он окна не сворачивает, только присылает
  `minimized`. Список свёрнутых — из демона через контракт.

## Слои

```text
внутри Hyprland:  прослойка Lua (~150 строк): сочетания → hl.dsp.global("wsdbus:…"),
                  статические правила; hyprbars из hyprland-plugins (W12)
wsdbusd:          provider (всегда) + policy (по конфигурации) (W11)
                  ─ socket1/socket2, global shortcuts, session bus
интерфейс окон:   QML на wsdbus-ctl (место — открытый вопрос)
```

hyprbars той же версии, что Hyprland; кнопки отправляют `wsdbus:minimize`,
`wsdbus:maximize`, `wsdbus:close`. Своего кода C++ нет. Код Hyprstack не
копируется, код Omarchy можно заимствовать с указанием источника (W13).

## `provider`

- подключение к socket1/socket2, смена экземпляра Hyprland, переподключение;
- `hypr-model` из `hyprctl clients/workspaces/monitors -j` и событий;
- `app.id` — поиск desktop-файлов по `StartupWMClass`, имени файла и id
  Flatpak в `XDG_DATA_DIRS` (`wsdbus-appid`), проходит
  `spec/appid-cases.json`;
- `keyboard.layout` — событие `activelayout`;
- `session.locked`, `appearance.*` — по итогам этапа 0;
- `Shortcut` — `sendshortcut`; `LaunchApp` — запуск desktop-файла;
- проверка песочницы отправителя (W20) на Rust, проходит
  `spec/sandbox-cases.json`;
- `display.brightness` нет: потребители берут яркость сами.

## `policy`, первая версия

- **режим для каждого стола (W19):** в конфигурации режим по умолчанию для
  каждого стола (`tiling` или `floating`); сочетание меняет режим текущего,
  другое — всех столов разом (массовая операция над той же моделью). Общие
  настройки Hyprland, которые зависят от режима (фокус под мышью и др.),
  переключаются при смене активного стола, как в Omarchy;
- **плавающий стол:** новые окна плавают по правилу Hyprland ещё до показа
  (правило по `workspace` или `window.open_early`); тег «сделано режимом» и
  тег «на плавающем столе», как в Omarchy; при выходе из режима в тайлинг
  возвращаются только окна с первым тегом;
- **свернуть:** перенос на `special:wsdbus-minimized-<monitor>` с записью,
  откуда окно ушло (стол, геометрия, плавающее ли); восстановить по записи;
  запрос `minimized` от приложения обрабатывается так же;
- **развернуть** и вернуть с сохранённой геометрией;
- **половины и четверти** экрана сочетаниями;
- **`Alt+Tab`:** порядок по последнему фокусу, включая свёрнутые, показ — в
  интерфейсе окон;
- **настройки режима** (отступы, рамки, фокус под мышью) сохраняются и
  возвращаются;
- **состояние сессии** в `$XDG_RUNTIME_DIR` по `HYPRLAND_INSTANCE_SIGNATURE`;
  после reload и перезапуска демона — пересинхронизация по тегам и файлу.

**Не в первой версии:** snap перетаскиванием с подсказкой зоны (нужен ввод в
compositor), overview, анимация сворачивания в панель.

## Состав (этот план)

```text
crates/
  wsdbus-appid/          поиск desktop-файлов для app.id
  hypr-ipc/              socket1/socket2, типизированные события, смена экземпляра
  hypr-model/            состояние окон, столов, режимов, записей; без IO
  hypr-policy/           (состояние, событие) → команды; без IO
  hypr-exec/             команды → dispatch/--batch/eval, подтверждение, пересинхронизация
  hypr-store/            состояние сессии по HYPRLAND_INSTANCE_SIGNATURE, теги
  hypr-shortcuts/        Wayland-клиент global shortcuts
  wsdbusd-api/           реализация Desktop1 поверх hypr-model, проверка песочницы
bin/
  wsdbusd/               демон: provider, policy по конфигурации
hypr/                    прослойка Lua и пример настройки hyprbars
tests/                   записанные потоки socket2, сценарии
```

Своего `hyprland-rs` не берём: IPC простой, а чужой крейт отстаёт от релизов.

## Этапы

| Этап | Содержание | Готово, когда |
|---|---|---|
| **0. Прототип** | проверка допущений (ниже) во вложенном Hyprland | все пункты подтверждены или найдены обходы, план уточнён |
| **1. `provider`** | `hypr-ipc`, `hypr-model`, `wsdbus-appid`, `wsdbusd-api`, `wsdbusd` без `policy` | во вложенном Hyprland `wsdbus-ctl watch` показывает фокус, столы, окна и раскладку; команды работают; повторы записанных потоков проходят |
| **2. `policy`** | `hypr-policy`, `hypr-exec`, `hypr-store`, `hypr-shortcuts`, прослойка Lua, hyprbars | первая версия `policy` работает во вложенном Hyprland по чек-листу; перезапуск демона и reload не теряют состояние |
| **3. Интерфейс окон** | QML свёрнутых окон и `Alt+Tab`; место — по открытому вопросу | в Hyprland свёрнутые возвращаются из интерфейса, `Alt+Tab` показывает список |
| **4. Интеграция** | Nix: `wsdbusd`, hyprbars из hyprland-plugins той же версии, что Hyprland; wsconfig: desktop flake, прослойка Lua в overrides, unit `wsdbusd` под `ws-hyprland-session.target`, сочетания `ws-window` в Hyprland, `ws check` в Hyprland | wsconfig ставит стек в generation Hyprland; сочетания `ws-window` работают в Hyprland; проверки зелёные в обеих сессиях |

Этапы 0–3 идут во вложенном Hyprland и не ждут миграции wsconfig на Hyprland.
Этап 1 — после этапа 1 плана 1. Этап 4 — после этапов 2–3 wsconfig
`docs/plans/hyprland.md` (runtime и управление сессией).

### Этап 0: что проверить

1. Hyprland 0.56.2 запускается окном внутри сессии GNOME, IPC доступен.
2. Новое окно на плавающем столе показывается сразу плавающим, без рывка:
   правило по `workspace`, иначе `window.open_early`.
3. Процесс на Rust получает действия global shortcuts от
   `hl.dsp.global("wsdbus:…")`.
4. Кнопка hyprbars вызывает `global` и доходит до демона.
5. Источник `session.locked` в Hyprland: событие от locker, `LockedHint`
   logind или запрос `hyprctl locked` без постоянного опроса.
6. Источник `appearance.*` в Hyprland: `org.freedesktop.appearance` портала
   Settings или схема Caelestia.
7. `sendshortcut` доставляет сочетание в окно не в фокусе так, как нужно
   `Shortcut(keys, app)`.

Итог этапа — заметка в `docs/validation/hyprland-stage-0.md`: что
подтвердилось, какие обходы приняты, изменения плана.

## Тестирование

- `hypr-model`, `hypr-policy` — таблицы и property-тесты без IO;
- `hypr-ipc` — разбор записанных событий и JSON;
- `tests/` — повтор записанных потоков socket2 через `hypr-policy` и
  поддельный `hypr-exec`;
- `wsdbusd-api` — общие тесты контракта из плана 1 против `wsdbusd` с
  поддельным IPC;
- живые тесты — вложенный Hyprland по чек-листу `docs/testing.md`, затем
  настоящая сессия после этапа 4.

## Риски

| Риск | Что делаем |
|---|---|
| Синтаксис правил и Lua API Hyprland меняются | всё это только в прослойке Lua; проверка при обновлении Hyprland в wsconfig |
| hyprbars отстаёт от релиза Hyprland | демон работает без заголовков, действия доступны сочетаниями |
| Рывок нового окна на плавающем столе | этап 0, пункт 2 |
| Нет события блокировки экрана | этап 0, пункт 5; без источника `session.locked` не объявляется в `Capabilities` |
| Пограничные случаи: несколько мониторов, диалоги, XWayland, Steam/Proton/Wine | сценарии в `tests/` по каждому найденному случаю; особые правила приложений — данные конфигурации, не код |
| Окна двигает и пользователь, и демон | теги на окне — источник истины, демон не возвращает окна, которые не трогал |

## Открытые вопросы

1. **Где интерфейс окон** (свёрнутые и `Alt+Tab`, только Hyprland, W18).
   Не определено (2026-10-17); решается до этапа 3. Варианты:
   - отдельное приложение Quickshell в wsdbus (`wsdbus-ui`) — рядом с
     контрактом, не зависит от Caelestia и wswidgets; ещё один процесс Qt и
     своя тема;
   - новая поверхность wswidgets — общий процесс и тема; привязывает
     wswidgets к оконной модели Hyprland, нужен захват клавиатуры;
   - доработка Caelestia — плагинов нет, по сути форк;
   - готовая панель задач (waybar `wlr/taskbar`, nwg-dock) — не знает
     состояния «свёрнуто», `Alt+Tab` не решает;
   - Touch Bar через wstouchbar — только mbp16, как дополнение.
